# macOS 27 DockSwipe 实验

独立验证横向原生桌面动画，不修改配置，不安装后台进程。
仅供 macOS 27 实验，使用私有事件格式。用户已确认独立序列动画有效。
事件构造已提取到 `MacinTouch/DockSwipe.c`，供测试程序和驱动共用。

## 编译

在仓库根目录运行：

```sh
mkdir -p build
clang -Wall -Wextra -Werror -O2 -framework ApplicationServices \
  tools/experimental/dockswipe-probe.c MacinTouch/DockSwipe.c -o build/dockswipe-probe
```

默认只构造事件、检查 CGEvent 字段序列化往返并打印日志，不发包：

```sh
./build/dockswipe-probe
./build/dockswipe-probe --cancel
./build/dockswipe-probe --invert
```

## 实机复测

先在「系统设置 → 隐私与安全性 → 辅助功能」中授权运行程序的终端。
如果程序依然返回权限错误，可将 `build/dockswipe-probe` 本身加入该列表。
不需要 sudo。程序拒绝在权限缺失时发包。

准备至少三个桌面，停在中间桌面；每条命令分开运行并观察约两秒的动画：

```sh
# 累计进度 0 → 1，然后 ended，退出速度为 0
./build/dockswipe-probe --post

# 相反方向：累计进度 0 → -1
./build/dockswipe-probe --post --invert

# 进度 0 → 0.35 → 0，再 cancelled；应回到原桌面
./build/dockswipe-probe --post --cancel
```

需要记录：画面是否连续移动、方向、松手后是否完成切换、取消是否回弹、
结束后正常鼠标和触控板操作是否恢复。`space-before/after` 仅为辅助诊断，
私有查询可能滞后，不能据此断言动画成功。Ctrl+C 会尽力发送 cancelled。
本实验暂不自动重发结束包，以免混淆首次发包的实际效果。

## 实现与验证边界

- HID payload 构造和 CGEvent 序列化注入改编自
  [joshuarli/iss](https://github.com/joshuarli/iss/blob/master/iss.c)，
  0BSD 许可随附在 `iss-LICENSE.txt`。
- 保留 DockControl 与 companion gesture 配对投递到 session tap 的方法。
- 改为 120 个 changed 帧、每帧约 16ms，连续推进而非瞬间高速切换。
- dry-run 通过仅代表事件可构造；不能证明 Dock 已接受 HID payload。
- 用户已实机确认：连续推进、反向推进、中途取消均正常工作。

独立发包已验证有效；驱动真实四指输入仍需实机验收。

## 四指驱动集成

macOS 27 默认开启四指左右滑动跟手，其他系统继续使用 Control+方向键。
上下滑动继续使用原行为。四指水平移动约 30% 触摸面宽度，进度达到 1；
反向移动会减小进度，第一根手指抬起时结束，剩余手指全部离开后才能再次开始。
GUI 停止、配置更新、第五根手指介入会发送取消事件；CLI Ctrl+C 也会取消。
暂时使用零退出速度，保持与已验证探针一致，快速甩动的惯性手感尚未实现。

复测方式（二选一，先退出旧驱动，避免两个进程同时发事件）：

```sh
make run-debug
# 或
make gui-run-debug
```

`fourFinger` 配置新增两个可选 JSON 字段，不影响旧配置读取：

- `nativeHorizontalSwipe: false`：回退为原有左右快捷键；缺省为 macOS 27 开启。
- `dockSwipeTravelFraction: 0.30`：完整进度所需宽度比例，允许 0.05–1.0。

重点复测慢速左右、移动一半退回起点、四指依次抬起、连续两次手势、
第一/最后一个桌面的边界、双指滚动切换到四指，以及上下滑动。
日志只打印原生手势的开始与结束进度，避免每个坐标刷屏。

不发系统事件的识别回归测试：

```sh

```

## 四指捏拢 / 张开

`DockSwipe` 的 motion 轴已扩展为：1 左右、2 上下、3 捏合。
四指捏合默认在 macOS 27 开启；使用原生 motion=3，负进度对应捏拢
（Apps / Spotlight 的应用视图），正进度对应张开（显示桌面）。
这两个方向来自开源实现，**当前尚未完成本机视觉验收**。
本次从工具宿主运行 `--post` 时辅助功能检查失败，没有发包。

检测采用六组指间距离的均值变化，要求至少三组距离同向变化，并且距离变化
显著大于中心平移。轴确定后锁定到结束，不会在捏合过程中突然切换桌面。
它识别的是四触点几何变化，不依赖 HID 提供“拇指”标签。
默认指间距离改变约 60% 达到完整进度；GUI 的 Four-Finger Gestures 中可调。
缩拢后全部抬手再重新落下，可再次张开以尝试反向操作。

新增可选配置：

- `nativePinchGesture: false`：关闭四指捏合（缺省在 macOS 27 开启）。
- `dockPinchTravelRatio: 0.60`：达到完整进度的距离变化比例，越小越敏感。
- `nativeVerticalSwipe: true`：试验性原生调度中心/App Exposé，缺省关闭，
  此路径尚未实机验证，上下滑动默认仍用快捷键。

独立排查发包路径（先按上面的命令重新编译 probe）：

```sh
# 张开：显示桌面
./build/dockswipe-probe --pinch --post
# 捏拢：Apps
./build/dockswipe-probe --pinch --post --invert
# 张开中途取消
./build/dockswipe-probe --pinch --post --cancel
# 仅验证可选的原生纵向轴
./build/dockswipe-probe --vertical --post
```

驱动复测：四指捏拢、四指张开、捏合一半反向拉回、手指依次抬起、
单独移动拇指、四指左右平移、双指捏合缩放，以及两种触摸模式。
观察 Apps 是否打开正确的应用视图、显示桌面是否可恢复、动画是否卡住。
与左右切桌面一样，末尾先使用零退出速度，后续按实测调整。

协议参考：
[Mac Mouse Fix TouchSimulator](https://github.com/noah-nuebling/mac-mouse-fix/blob/master/Helper/Core/Touch/TouchSimulator.m)
及 [dockswipe](https://github.com/oomol-lab/dockswipe) 的轴定义；
HID 序列化仍基于随附 0BSD 许可的 iss 实现。

## 捏合轴无响应后的原生构造对照（2026-10-29）

用户已确认原 serialized-baseline 的 pinch 正负两个方向完整发到 ended，均无效果。
`--native-hid` 是独立诊断后端，不修改驱动：动态调用 IOKit 的 IOHIDEventCreate、
字段 setter、子事件 API，再调用 SkyLight 的 SLEventSetIOHIDEvent 附加事件。
不使用 CGEvent 内存偏移，也不假设私有事件的字节布局。

与 baseline 的对照：系统生成的 serialized HID 队列头 options 含 phase，
原手工 payload 队列头 options 为 0；系统构造的位置默认值为 0，baseline X 为 0.1。
这些是已观察到的格式差异，尚不能视为实机失败根因。

该参考测试同时使用非零起始进度、累计进度 ±1.5、结束速度 ±1.25，
不再发送 companion 29（对应 Mac Mouse Fix 的 macOS 27 路径）。

```sh
./build/dockswipe-probe --pinch --native-hid --post
./build/dockswipe-probe --pinch --native-hid --post --invert
```

默认不带 `--post` 可检查 API 构造是否成功；不代表 Dock 已接受事件。
原来的 probe 参数保持原行为，便于比较。


## 原生构造验证结果与驱动接入（2026-10-29）

用户已确认 `--pinch --native-hid --post` 及反向测试有效。
因此验证结论限定为：原生 API 构造 + 非零起始进度 + ±1.5 范围 + 非零结束速度
这一组合有效，尚未通过逐项对照证明某一个字段是唯一原因。

已将原生构造移入 `MacinTouch/DockSwipe.c`，独立 probe 与驱动共用。
驱动的 motion=3 改用该路径，不发送 companion 29；横向切桌面保持已验证的旧路径。
识别进度仍为 ±1，输出层映射为 ±1.5；首次事件携带已识别的实际位移，
结束速度按最后的进度增量估算并限幅，反向拉回或回到原点时取消。
真实四指输入的识别、灵敏度和松手行为需要再次验收。


## 五指兼容

捏合、张开和多指滑动现接受 4 或 5 个触点。第五指在识别方向前落下时，
会保留已有触点的原始起点，只为新触点建立基准，不清空已产生的捏合位移。
方向锁定后保留原参与触点，额外第五指的加入和抬起不会让动画跳变或取消。
任一参与触点抬起后结束，等待全部离开再接受下一次；超过五指时取消。

回归测试已覆盖：五指捏拢/张开、第五指延迟落下、锁定后加入/移除第五指、
六指取消，以及原有四指与左右切桌面用例。真实五指操作仍需实测。


## 五指灵敏度与向上轻扫竞争优化

当前稳定基线已提交为 `a04855e`。后续优化包括：

- 第五指加入前已发生的位移继续计入识别，不再整体重置起点和计时。
- 捏合使用同方向最明显的三组相对距离变化，避免拇指动作被五指的十组距离平均稀释。
- 允许一组指间距离反向变化，适应手指自然弯曲，但仍要求至少三组距离支持捏合。
- 出现初步捏合证据时暂缓平移判定；上滑/左右滑动要求至少三个触点沿整体方向移动，
  避免单个拇指造成的重心漂移打开调度中心。
- 四指、五指使用同一相对变化阈值；原生发包后端和桌面切换路径不变。

回归测试覆盖了小幅收拢时四/五指一致性、保留迟到触点前的位移、伴随向上漂移的捏合，
以及正常五指向上轻扫。真实操作灵敏度仍待实测。


## 统一多指识别

在回退的 `14b10a6` 基线上，新增 `MultiFingerRecognition.swift`：

- `MultiFingerEvidence` 每次从一份参与触点快照计算中心位移、指间缩放、
  缩放一致性、平移支持指数量和最大单指位移，三个候选共用。
- `MultiFingerArbiter` 统一竞争捏合、横向、纵向及长按；明确结果锁定到抬手。
  斜向或平移/缩放混合证据暂不输出，轻微径向变形与平移竞争时至少观察 60ms，
  再检查平移是否占据明显优势；证据仍接近则继续观察。清晰平移、清晰捏合不额外等待。
- 识别不读取输出后端配置；快捷键路径和原生路径使用相同的候选选择。
  快捷键的既有距离/速度触发限制保留在输出调度部分。
- 四指与五指、迟到第五指的基准保留、原生协议构造沿用现有实现。
- 没有重新加入已回退的断触恢复、速度衰减或反向取消迟滞。

纵向输出现已接入原生动画，见下节；显式关闭原生输出时仍使用快捷键。
日志 `Unified recognition selected=...` 可直接看到最终选择的种类和对应运动指标。
回归新增：相同规则下的横向/纵向选择、斜向等待、混合证据按单调时间解决、
捏合/轻扫/长按种类锁定，以及调度中心快捷键仅输出一次。


## 原生上下轻扫与上滑/张开区分

macOS 27 的 `nativeVerticalSwipe` 缺省现为开启，显式 false 仍回退快捷键。
纵向 motion=2 使用与有效捏合相同的系统 IOHIDEvent 构造后端，不再用手工序列化数据；
上滑为调度中心、下滑为 App Exposé，输出连续进度。GUI 可切回原有快捷键。

识别新增共同行进组：至少三根手指位移向量接近、其余手指明显滞后时，
按轻扫候选观察，不把滞后拇指造成的间距变化当作张开。
只有一两根手指先移动而像捏合时，观察约 16ms，等待同一报告的后续触点；
如果没有新 HID 更新，候选定时检查也会完成确认，避免手指停住后无法触发。
这些是识别确认机制，不包含已回退的断触续接。

张开行程独立为 `dockSpreadTravelRatio`，默认 1.0，捏拢仍为 0.60。
GUI 的 Spread travel 可调至 0.4–2.0，越大越不容易过早走满动画进度。

新增测试：四/五指滞后拇指时的逐触点上/下滑、部分报告确认、默认纵向原生输出及方向、
张开较长行程、无后续 HID 输入时的候选确认。真实上下跟手手感仍需实机验收。

## 多指手势保持鼠标位置

移除了原生手势开始时的 mouseMove，以及旧上滑快捷键路径结束后将光标移到顶部的行为。
多指手势开始、更新、结束和取消不再主动发送鼠标移动；回归测试统一检查没有指针事件。
单指光标操作保持原行为，因此多指依次落下、尚未形成多指接触前的首指移动仍可能移动鼠标。

## 张开漏识别与斜向轻扫误判

平移候选改用多数手指的共同方向及位移中位数，不要求各指移动距离接近。
至少三指且占移动手指的 80% 同向时优先保留轻扫；有缩放证据时观察 35ms，
避免各指速度不同或拇指滞后引起的指间距变化抢先锁定张开。
方向轴优势比从 1.3 调为 1.15，接近 45 度时仍等待明确方向。

缩放方向按支持的指间对数量选择，缩放量使用中位数，减少单个短距离指间对的影响。
增加三指径向运动支持，允许一指暂时反向；像素阈值随初始手形大小调整。
保持 10% 缩放启动要求和部分 HID 报告确认，微小抖动不触发。

回归覆盖四/五指 20、35、60、75 度双向轻扫、不同手指速度与停滞触点、
一指反向的张开、小手形张开及微抖动。测试仅捕获输出动作，实际识别手感需实机确认。

### 五指捏合与纵向轻扫竞争

初始手形中，某触点最近邻距离同时超过其余触点中位数的 1.4 倍及最大值的
1.2 倍时，将其估计为拇指。HID 没有解剖标签；几何证据不足时不指定拇指。
估计仅依赖初始位置，不随当前运动重新分配。五指时拇指与其余四指相向或背向
运动，优先使用双方间距变化识别捏合/张开，避免四指近乎平行移动被抢判轻扫。
纵向轻扫排除已估计的拇指，需要其余四指在场（至少三指方向一致）；
只有三根普通手指加拇指时不触发纵向轻扫。横向滑动沿用现有规则。
日志增加 thumb 和 fingerVerticalVotes，便于实机检查估计结果。
回归覆盖左右镜像手形、双向开合、四指滑动且拇指静止，以及三指加拇指排除。

已识别拇指时，开合方向及连续进度统一使用拇指到其余手指的距离缩放中位数。
不再让四根普通手指内部的六对距离变化覆盖四对拇指距离，也不在拇指先动、
其余手指随后参与时切换缩放算法。相向运动仍只用于捏合优先级判定。
回归增加内部手指收拢但拇指张开及其反向情况，以及其他手指稍后参与时的方向一致性。

### 开合诊断日志

默认 info 级别的 fourFinger 分类输出 `PinchTrace`，按 seq 关联一次手势。
候选、选定、原生开始、活动和结束均有记录；活动快照最多约每 80ms 一次，
开合符号、拇指估计或阶段变化立即记录。此日志仅观测，不修改识别或输出。
direction=spread/正 scale 表示张开，pinch/负 scale 表示捏合。
source 为方向来源，thumbScale 为拇指距离缩放，pairScale 为全指间对投票结果；
pairSupport、pairs（按触点 ID 排序逐对）、points（屏幕坐标起点>当前）用于复核。
coherent、parallel、pan、verticalVotes 和 ambiguous 用于检查轻扫竞争。
progress 是归一化动画进度；现有 DockGesture 日志记录实际输出开始/结束的
phase、映射后的 progress、velocity，可检查系统投递前后的方向。

停止已有驱动后，可在终端保存完整复现日志：

```bash
make run-debug 2>&1 | tee /tmp/macintouch-gestures.log
```

如果自定义了日志过滤，需将级别设为 info 或 debug，并启用 fourFinger 分类
（分类列表为空表示全部开启）。提供从一次落指到抬手的完整日志，并标注实际做的是张开还是捏合。

### 未识别阶段的短暂缺点

实机日志出现五指开始后约 40–66ms 单点丢失、约 23ms 后恢复，旧逻辑立即结束
并等待全手抬起，导致后续张开被忽略。现仅在尚未选定任何手势、缺失不超过两个原触点、
至少三点仍在时等待最多 60ms；同 ID 恢复保留原始落点及位移，重置候选竞争。
等待中不输出动作，取消长按及候选确认计时；重复缺点报告不延长截止时间。
超时、替换 ID、剩余不足三点或全手抬起仍结束。已选定的手势继续首指抬起即结束。
日志新增 contact-gap、contact-restored、contact-gap-timeout。此限定机制不恢复
之前回退的活动手势断触续接、速度衰减或反向迟滞。

补充实机序列显示第二个触点会紧接着消失，原先单点限制会在等待到期前结束。
现覆盖五→三→四→五的分步恢复，第二点消失不延长首次 60ms 截止时间。
日志新增 contact-gap-update，结束行始终列出 expected/actual，便于排查剩余的 ID 替换或更深缺点。

### 缺点期间继续分析真实触点

后续实机第三次捏合在 60ms 截止时仍只剩三个原触点；此前等待阶段完全跳过
几何分析，samples=1 并不代表手没有移动。候选窗口现为首次缺点后的 120ms，
不因后续缺点延长。三个及以上原触点的集合稳定 16ms 后，使用其原始落点及
实际当前位置继续分析，仅允许选定捏合/张开；不模拟缺失坐标，不允许缺点轻扫。
有原始拇指估计时要求它仍在场，并保留该身份；拇指缺失则继续等待。
选定后冻结实际参与触点，恢复原生连续进度及首指抬起结束规则。
新三指接触本身仍不能启动多指候选，只用于已由四/五指启动的候选。
日志新增 candidate-partial、partial-pinch-selected，覆盖缺点期间的几何证据。
回归包括三个真实触点的捏合和张开、静止拇指加两指捏合、缺点平移不触发轻扫、
迟到触点不影响锁定进度、固定超时及抬手结束。

### 触点生命周期与过滤诊断（仅日志）

Contact ID/组帧实验已回退，当前仍使用原有输入路径。
info/fourFinger 下新增 TouchTrace：raw-DOWN/raw-UP 记录 PRESS cookie、原值、
当前槽位、设备报告数量、跟踪列表、过滤剩余时间；DOWN-accepted、DOWN-skipped
区分正常纳入、event-filter、missing-coordinate-in-last-20-events。
UP-removed/UP-skipped 记录删除或未知触点；coordinate-skipped 对每个槽位在下一次
PRESS 前最多记录一次，避免逐坐标刷屏。filter-start 标注 two-finger-scroll-ended，
filter-expired 是下一次输入时观测到已到期（不是精确的定时回调）。
mouseDown/mouseUp/rightClick/doubleClick 实际分发也记录 TouchTrace action，
用于判断点击是否在多指动作中发出。此轮不修改过滤、坐标重建或手势判定。

### 候选结束防抖

seq=8 实机序列在首个 UP 后 13ms 短暂降至两指，同毫秒恢复三指，9ms 后恢复五指。
未选定手势时，非零的一/两指快照现只等待，不做运动判定、不确认长按，
仍使用首次缺点起算的 120ms 截止时间。恢复至少三指后重新观察稳定触点集合。
四指候选中迟到第五指可以先于原触点恢复；候选成员总数最多五个，保留原始
落点且不延长截止时间。全手抬起、截止到期、超过五个成员或重置仍结束。
已选定手势的首指抬起结束行为不变。此次不涉及 HID 组帧或 Contact ID 改造。
回归覆盖四/五指短暂降至一/两指恢复、固定超时、全手抬起后新基准，及
四→三→两→三→迟到第五指→完整五指的顺序。

### 静止轻点先同步悬停位置

实机第一次点击记录 targetCG=(1145.9,363.1)、pointerBeforeCG=(579.0,504.4)，
DOWN 后指针到达目标，但静止轻点没有先发 mouseMoved。调度中心可能仍按旧悬停状态响应，
该推测需要实机验收，日志本身不能证明系统内部命中目标。
现只在抬手确认为单指轻点时，先向同一触摸落点发 mouseMove，再发按下/抬起或双击。
不在 DOWN 时提前移动；多指取消和保护期间不发此对齐事件。日志增加 tap-align-before-click。
ClickTrace 继续记录事件目标和发送前指针，验证移动是否生效。单指回归只捕获动作，
覆盖静止轻点、同点事件顺序、双击、多指取消及保护期；不向系统发鼠标事件。

### 多指松手后的单指保护

实机反馈全手抬起立即清除保护会降低收尾保护效果，已撤销该实验。
恢复原有 fourFingerProtectionDuration（默认 0.8 秒）保护，不因瞬间 activeTouches
清空而提前解除，防止迟到报告或尾指重新出现被当成新单击。保留轻点落点同步与诊断日志。
回归覆盖多指尾指、短暂零触点后重新落指仍受保护，以及保护期结束后的正常点击。

多指收尾保护现默认 300ms（fourFingerProtectionDuration=0.3），保留固定时间保护机制，缩短正常单指操作的等待。本机保存配置也同步为 0.3；其他已有配置仍沿用其保存值。

## 双指连续滚动与惯性

双指滚动现输出连续像素滚动及显式 scrollPhase（1 began、2 changed、4 ended、8 cancelled）
和 momentumPhase（1 begin、2 continue、3 end），经公开 CGEvent 字段设置；不用 DockSwipe。
单指滚动保持原事件路径。直接滚动和惯性锁定同一个目标位置，避免松手后跳到光标下的其他区域。
首根参与手指抬起即结束直接滚动；增加第三指、范围失效或重置不产生新惯性。
通过过滤且坐标有效的新 DOWN 会中断双指惯性，发送必要的 momentum end；被过滤或缺少坐标的 DOWN 不影响惯性。
切换其他手势不设置滚动的 DOWN 过滤窗口；正常松手仍保留原有 100ms 过滤配置。

惯性使用单调时钟、最新样本有效期、实际回调间隔及按时间换算的衰减，Timer 加入 common 模式。
停住超过速度窗口（默认 100ms）再抬手不沿用旧速度；小数尾速继续累计，不按每帧 0.5 像素直接丢弃。
传统映射的惯性 Y 方向与直接滚动保持一致；开启平滑时修正新旧样本权重顺序。
鼠标清理只释放驱动自己持有的左键，不依据物理鼠标按钮状态操作其他按键。

双指识别比较中心净位移与间距净变化，删除“20 次回调就默认滚动”的启动条件，避免静止抖动误触发。
识别滚动后保留从候选起点已经移动的距离。缩放仍使用现有 magnify 输出。

回归 tools/experimental/scroll-tests.swift 仅捕获动作，不向系统投递事件，覆盖阶段、目标位置、
直接/传统映射与 Y 反转、暂停后抬手、惯性中断、手势切换、重置、静止抖动和双指缩放区分。
实机请测试网页/列表的慢拖、快速甩动、停住后抬手、惯性中重新落指及双指转四指。

惯性手感首轮调整：衰减 0.98→0.94，停止速度 10→20px/s，速度估计窗口
100→60ms，加速增益 1.5→2.4，上限 2.0→2.6；本机保存配置同步。
相同起速 1000px/s 时，理想衰减至停止阈值约从 3.8 秒缩短到 1.05 秒。
这里加速增益作用于松手后的惯性起步；手指直接拖动仍保持原有映射。

距离偏短后第二轮调整：衰减 0.94→0.96，保留停止速度 20px/s 及起步增益；相同起速下滑行距离约增加 50%，1000px/s 理想持续时间约 1.6 秒。本机配置同步。

在不延长惯性时长的前提下增加距离：新增可选 inertialDistanceMultiplier，缺省及本机值为 2.0。
仅将惯性输出位移乘以 2，衰减速度、停止阈值、起速及直接拖动保持原样；
不通过增加内部速度或减慢衰减延长尾巴。旧配置省略新字段仍可解码。
回归用相同时钟并行模拟 1x/2x，检查停止时刻一致、位移约两倍（容许整数像素舍入）。

### 惯性漏触发的速度采样

此前只留最近 30 次 HID 回调，密集 X/Y 更新会将样本跨度压缩到 16ms 以下并被拒绝；
识别滚动前的运动也未计入速度。现按固定 4ms 时间桶合并回调、按速度时间窗保留样本，
保留候选最初位置和单调时间。短于 inertialMinTimeInterval 的真实动作以该值作为保守分母，
不再直接拒绝；不改变起速门槛、位移倍数及衰减。缺乏时间基准、停顿超时仍不产生惯性。
ScrollTrace release/inertia-start/inertia-skipped/inertia-stop 记录样本跨度、末次样本年龄、速度、
门槛及停止原因，区分没启动与启动后立即被 DOWN 回调打断。范围越界也单独记录。
回归覆盖 20ms 内 100 次回调、8ms 单次更新甩动及识别前位移贡献；原有暂停、阶段和时长检查保留。

### 弹射后快速衰减

惯性改为连续速度曲线 v(t)=v0·(1+6t/τ)·exp(-t/τ)，τ 为原指数时间常数的 1/7。
默认衰减 0.96@60Hz 时约 49ms 达到约 2.6 倍速度峰值，随后迅速制动；
起速 1000、停止阈值 20 时约半秒收尾。曲线积分与原指数模型相等，保留距离倍数，
把相同的行程集中到前段，不靠长尾获得距离。具体结束时间仍取决于起速。
每帧用积分差输出位移，避免刷新率或 Timer 抖动改变总距离。停止判定使用未乘距离倍数的
曲线速度且等待越过峰值；新触点、取消及阶段协议保留。日志记录 launch-brake 及 peakMs。
纯曲线回归覆盖初段加速、约 50ms 峰值、快速收尾、总积分保留和 30/60/120Hz 位移一致；
滚动回归继续覆盖短促甩动、双倍距离但同一结束时刻、方向与惯性中断。

弹射曲线第二轮：前段仍约 50ms 达峰，用 smoothstep 拉起；尾段改为单独的指数衰减，
时间常数为原始指数模型的一半。对起速 500/1000/2000、阈值 20，预计分别约
0.81/0.95/1.10 秒结束。峰值按积分重新归一化，保留总距离及独立的 2x 位移倍数，
不是把原来的半秒曲线整体减速。回归新增常见起速约一秒收尾的验证。

### 过滤的 DOWN 不能先行打断 fling

实机首次及末次 fling 都成功估速并启动，但 9ms 后收尾 UP/DOWN 回调在过滤窗口内
先触发 stopInertialScrolling，随后才被 DOWN-skipped 拒绝，导致 hadMomentumOutput=false。
现仅在通过过滤且重建出有效坐标后停止惯性；被忽略的回调不再改变双指或单指惯性状态。
正常新落指仍立即停止；停止日志标注 accepted-touch-down，曲线、速度和距离配置保持不变。

### 缩放收尾误触双击

实机缩放结束后 14ms 出现 UP/DOWN 换序，9ms 的新单指回调被当作 doubleClick。
原单指实现把所有非右键的 UP（包括多指收尾、拖动及被抑制的触点）写入双击历史。
现只有实际发出的单指轻点才更新双击历史；取消、多指及其他非轻点路径清空历史。
双指缩放正常抬手结束后，使用既有 eventFilterDuration（默认 100ms）过滤收尾 DOWN，
日志 reason=two-finger-pinch-ended；转为三指以上手势不设置过滤，避免吞掉新触点。
正常单指连拍仍保留双击。回归覆盖多指 UP 后新轻点不会变双击、缩放收尾过滤，
以及缩放转多指不屏蔽输入。

### 双击事件序列

第一击已经作为 mouseDown/mouseUp 发出后，第二次轻点改为 secondClick 动作，只发送
clickState=2 的一组 DOWN/UP；普通第一击显式 clickState=1。避免先单击再完整双击造成三击，
正常连拍路径也不再额外阻塞 50ms。距离判定保持原样。
单指滚动模式第一击尚在延迟队列时的快速连拍仍发送完整双击；第一击已发送的分支改为 secondClick。
ClickTrace event=SECOND_CLICK 与 TouchTrace action=secondClick 标记后半次点击。
回归同时构造（不投递）CGEvents 验证总计四个事件、clickState=[1,1,2,2]，
并验证单指滚动的第一击已发/未发两条路径及普通单指双击动作。

### Photos 双击成功/失败对照与投递观察

用户对照：成功组抬手间隔 150ms、两落点偏移约 4.8；失败组 161ms、偏移约 1.4。
两组都走普通第一击+secondClick，不能据此归因于距离或时间。原第一击使用 HID 事件源，
第二击使用 nil；现鼠标移动和左键事件统一复用同一个 hidSystemState 事件源。
有 info/fourFinger 日志时，首个点击按需创建只读 annotated-session 事件观察器，只记录
带本驱动标记的 DOWN/UP：ClickTrace delivered 包含 clickState、sourceState、targetPID、
最终事件坐标。它证明系统投递阶段的事件内容，不证明 Photos 内部控件已经处理。
观察器创建失败会明确提示 delivery-observer-unavailable；不拦截或修改输入，也不改变距离规则。
当前自动执行环境未获辅助功能授权，不能声称已在 Photos 内完成真实双击验收。
